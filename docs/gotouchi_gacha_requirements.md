# ご当地ガチャ 要件定義書

- バージョン: 1.0
- 作成日: 2026-10-31
- 想定開発期間: 8時間以内（ハッカソン）
- 実装担当: Codex

## 1. 目的・背景

日本各地の観光スポットをランダムに紹介し、利用者が普段調べない地域の観光資源を発見するきっかけを作る。地域活性・観光をテーマにしたハッカソンのMVPとして、シンプルで実際に操作できるWebアプリを構築する。

## 2. スコープ

### 必須（MVP）

1. 都道府県を「全国」または47都道府県から選択できる。
2. 選択条件に合う実在の観光スポットをランダムに1件表示できる。
3. 「全国」では都道府県を等確率で抽選し、続いてその県の観光スポットを抽選する。
4. 観光スポット名・都道府県名・Google マップへのリンクを表示する。
5. 写真が取得できる場合のみ表示する。取得できない場合はプレースホルダーを表示する。
6. 「もう一度回す」で再抽選できる。
7. ローディング・該当データなし・API失敗時の状態を適切に表示する。
8. PCとスマートフォンで使えるレスポンシブUIを提供する。

### 今回は対象外

- レアリティ、カテゴリフィルタ、訪問者数によるランキング
- ログイン、ユーザー登録、DB、課金
- GPSチェックイン、旅行経路最適化
- SNS共有、図鑑、履歴保存（時間が余れば拡張可能）

## 3. 想定ユーザー・利用シナリオ

- 旅行先を決めていない人が「全国」でガチャを回し、未知の観光スポットを発見する。
- 特定県へ旅行する人がその都道府県を選択し、候補をランダムに探す。
- 結果からGoogle マップを開き、場所や行き方を確認する。

## 4. 画面要件

### 4.1 メイン画面（単一ページ）

- タイトル「ご当地ガチャ」と簡単な説明
- 都道府県セレクトボックス（初期値「全国」）
- 「ガチャを回す」ボタン
- 結果カード（抽選後に表示）
  - 観光スポット名
  - 都道府県名
  - 写真（利用可能な場合）またはプレースホルダー
  - 「Google マップで見る」リンク（新しいタブ）
  - 「もう一度回す」ボタン
- データ取得中は操作の二重送信を防ぎ、進捗表示を行う。
- 抽選演出は短いフェード・カード切り替え程度とし、実装時間を優先する。

### 4.2 UI状態

- 初期状態: 未抽選
- 読み込み中: ボタン無効化・ローディング表示
- 成功: 結果カード表示
- 0件: 対象スポットが見つからない旨と再試行導線
- エラー: 取得に失敗した旨と再試行導線

## 5. 機能要件

| ID | 機能 | 仕様 | 優先度 |
| --- | --- | --- | --- |
| F-01 | 都道府県選択 | 「全国」＋47都道府県から単一選択 | 必須 |
| F-02 | スポット取得 | OpenStreetMap の Overpass APIを利用し、観光スポット候補を取得 | 必須 |
| F-03 | 都道府県抽選 | 「全国」選択時は47都道府県から等確率で選ぶ | 必須 |
| F-04 | スポット抽選 | 対象県の取得済みスポットから等確率で1件抽選 | 必須 |
| F-05 | 結果表示 | 名称・県名・写真（あれば）・地図リンクを表示 | 必須 |
| F-06 | 再抽選 | 同じ選択条件で何度でも抽選可能 | 必須 |
| F-07 | キャッシュ | 同じ県のデータを短時間で再取得しない | 必須 |
| F-08 | エラー処理 | タイムアウト、通信エラー、0件を考慮 | 必須 |

### 5.1 抽選ルール

- 特定県が選択された場合、その県内の候補から1件抽選する。
- 「全国」の場合、最初に47都道府県から等確率で県を選び、その県の候補から1件抽選する。
- 抽選された県に候補がない、または取得できない場合は、理由をログに残し、別の県で数回まで再試行する。再試行後も失敗する場合はエラーを表示する。**取得できない県を除くと厳密な等確率は保証できない**ため、画面やREADMEにその制約を明記する。
- 同一スポットの連続出現を避けることは必須としない。
- ガチャの抽選はキャッシュ済み候補に対してクライアント側で実施してよい。

## 6. 観光スポットデータ

### 6.1 データソース

- OpenStreetMap / Overpass API（無料・APIキー不要）
- 対象タグ例: `tourism=attraction`, `tourism=museum`, `tourism=viewpoint`
- `name` がある要素を対象とする。
- `node`、`way`、`relation` に対応し、way/relationは `out center` で得た代表座標を利用する。
- OpenStreetMapのデータには欠損や偏りがある。取得結果は公式観光地一覧と同一ではない。

### 6.2 データモデル

```ts
type Prefecture = {
  code: string; // 例: "04"
  name: string; // 例: "宮城県"
};

type TouristSpot = {
  id: string; // 例: "node/123456"
  name: string;
  prefectureCode: string;
  prefectureName: string;
  latitude: number;
  longitude: number;
  imageUrl?: string;
  osmUrl?: string;
};
```

### 6.3 取得クエリ例（宮城県）

```overpass
[out:json][timeout:25];
area["name"="宮城県"]["boundary"="administrative"]["admin_level"="4"]->.searchArea;
nwr["tourism"~"^(attraction|museum|viewpoint)$"]["name"](area.searchArea);
out center;
```

実装時は県名を固定リストから選び、ユーザー入力をそのままクエリへ埋め込まない。Overpassのエリア検索結果が0件になる場合に備えてエラー処理する。

### 6.4 写真

- OSMタグの `image` や `wikimedia_commons` 等から**直接表示可能で利用条件を確認できる**画像URLが得られる場合のみ使用する。
- 画像URLがない場合はプレースホルダーを表示し、写真取得のための複雑な外部API連携はMVPでは行わない。
- 写真を表示する場合は著作権・ライセンス・クレジット要件を満たすこと。安全に確認できない場合は表示しない。

### 6.5 地図リンク

- スポット座標からGoogle マップの検索リンクを組み立てる。
- 例: `https://www.google.com/maps/search/?api=1&query=<緯度>,<経度>`
- Google Maps Platform APIキーは不要（外部サイトへのリンクのみ）。

## 7. システム構成・実装方針

- Next.js（App Router）+ TypeScript
- Tailwind CSS
- データベース・認証なし
- 都道府県リストはローカル定数ファイルで管理
- Overpass APIへのアクセスはNext.jsのRoute Handler（例: `GET /api/spots?prefecture=04`）を経由する。
- APIレスポンスは正規化し、重複と名称・座標の欠損を除外する。
- 同じ都道府県の取得結果をキャッシュする（Next.js側のキャッシュまたはインメモリ。ホスティング環境で永続保証がない点に注意）。
- Overpassの公開エンドポイントに過剰なリクエストを送らない。タイムアウトを設定し、失敗時はエラーを返す。
- **8時間での完成を優先し、最初は宮城県の固定JSONでUI・抽選を完成させてからAPI連携する。** API障害時のデモ用にサンプルJSONを残す。
- OSMのデータを利用している旨と適切な帰属表示（© OpenStreetMap contributors）を画面に表示する。

## 8. 非機能要件

- レスポンシブ: スマートフォン幅でも選択・抽選・結果閲覧ができる。
- パフォーマンス: キャッシュ済み候補からの抽選は即時に行う。初回取得は外部APIの応答に依存する。
- 信頼性: 通信エラーやデータ0件でも画面がクラッシュしない。
- セキュリティ: APIパラメータは47都道府県コードのホワイトリストで検証。外部データは文字列として安全に描画する。
- アクセシビリティ: ボタンのラベル、キーボード操作、読み込み状態の通知を考慮する。
- 利用規約: OSM/Overpassと画像ソースの利用条件・帰属表示を守る。

## 9. 受け入れ条件

1. 初期表示で「全国」が選択されている。
2. 都道府県リストに47都道府県が過不足なく表示される。
3. 「宮城県」を選んでガチャを回すと、宮城県の候補だけが表示される。
4. 「全国」を選ぶと、抽選された都道府県の候補が表示される。
5. 結果カードからGoogle マップを開ける。
6. 写真がなくてもプレースホルダーで結果を表示できる。
7. 再抽選でき、読み込み中の連打で処理が重複しない。
8. データ0件・APIエラー・タイムアウトでもユーザーに適切なメッセージが表示される。
9. スマートフォンとPCでレイアウトが破綻しない。
10. デモ用の固定JSONでも主要な操作ができる。

## 11. Codexへの実装指示

1. この要件定義書を基準に、動作するNext.jsアプリを作成する。
2. MVP以外の機能を勝手に追加しない。
3. **最初に固定データで動作する縦切りのMVPを完成**させ、次にOverpass API連携を実装する。
4. 外部APIが利用できない場合も、サンプルデータでデモできるようにする。
5. 抽選処理とOverpassレスポンスの正規化処理はUIから分離し、テスト可能にする。
6. READMEにセットアップ・起動・デモ方法・データソース・既知の制約を記載する。
7. 実装後にlint/buildを実行し、可能なら抽選処理の簡単なテストを追加する。

## 12. 未決事項・設計上の割り切り

- 写真は必須ではない。画像の自動補完は対象外。
- 全国の全スポットを事前に収集する方式ではなく、抽選された県のデータを必要に応じて取得する。
- 全国抽選の県ごとの厳密な公平性は、API失敗・0件による再抽選が発生すると崩れる。
- 観光スポットの品質・掲載漏れ・閉業情報はOpenStreetMapに依存する。
- ガチャは「観光地を知るきっかけ」を提供するものであり、旅行予約や訪問を保証するものではない。
